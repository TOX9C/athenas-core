## THE REMAINING BUG (this is your job)

The poller now successfully calls `pty_agent_info`, but it **always returns `fg="shell"`**, even when `claude` is running in the pane. Confirmed via console log:

```
[AgentInfoPoller] pane=19ecc8a9d3e-0 fg="shell" title=None session_exists=true
```
...printed 243+ times, never changing to `"claude"` after the user runs `claude` and types into it.

### Root cause (high confidence — please verify)

The backend detection in `src-tauri/src/commands/mod.rs:1224` (`pty_agent_info`) and its twin `:1327` (`pty_foreground_process`) both use:

```rust
let pgid = s.pgid.as_raw();                                  // line 1240
// ...
std::process::Command::new("ps")
    .args(&["-o", "command=", "-g", &pgid.to_string()])      // line 1251-1252
```

**`s.pgid` is the SHELL's process group**, captured once at PTY spawn time (`crates/athena-terminal/src/session.rs:92`, `pgid: nix::unistd::Pid`, assigned during `fork`). When the user runs `claude` interactively, zsh/bash **job control** puts `claude` into its OWN new process group (`setpgid`) and makes it the foreground group of the controlling terminal (`tcsetpgrp`). So:

- `ps -g <shell_pgid>` lists only processes still in the shell's group = just the shell itself.
- `claude` is in a DIFFERENT process group, invisible to this query.
- The loop finds only the shell line, skips it (it's in `shell_names`), falls through, and `detected` stays `"shell"`.

### The correct fix

Query the **foreground process group of the PTY's controlling terminal**, not the stored shell pgid. The backend has the master fd (`s.master_fd`, an `AtomicI32` at `crates/athena-terminal/src/session.rs:86`). The foreground pgid of a tty is obtained via:

```c
pid_t fg_pgid = tcgetpgrp(master_fd);   // libc
```

Then `ps -g <fg_pgid>` lists the actual foreground process group (claude/codex). When the shell is idle (no foreground job), `tcgetpgrp` returns the shell's own pgid, so the query correctly falls back to "shell" — exactly the desired behavior.

**Concrete suggested implementation** (`src-tauri/src/commands/mod.rs`, both `pty_agent_info` ~1240 and `pty_foreground_process` ~1336):

Replace:
```rust
let pgid = s.pgid.as_raw();
if pgid <= 0 { /* return shell */ }
```
with something like:
```rust
let master_fd = s.master_fd.load(std::sync::atomic::Ordering::Acquire);
if master_fd < 0 { /* return shell */ }
let fg_pgid = unsafe { libc::tcgetpgrp(master_fd) };
if fg_pgid <= 0 {
    // tcgetpgrp failed (e.g. fd closed) — fall back to the stored shell pgid
    fg_pgid = s.pgid.as_raw();
}
if fg_pgid <= 0 { /* return shell */ }
```
and use `fg_pgid` in the `ps -g` query. (`libc` is already a dependency — it's used in `crates/athena-terminal/src/session.rs` for `ioctl`, `dup2`, etc.)

**IMPORTANT macOS/edge considerations to handle:**
- `tcgetpgrp` on the *master* pty fd: on macOS, `tcgetpgrp` on a pty master returns the foreground process group of the slave's session. This is exactly what we want. Verify behavior; if the master doesn't work, the alternative is `ioctl(fd, TIOCGPGRP, &pgrp)`.
- When the shell is at a prompt (idle), `tcgetpgrp(master)` == shell pgid → "shell" (correct).
- When `claude` is running, `tcgetpgrp(master)` == claude's pgid → detect "claude" (correct).
- When `claude` exits back to the shell, it reverts automatically (correct).
